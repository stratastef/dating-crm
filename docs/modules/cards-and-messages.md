# Cards and messages

A card is one match. Routes are in `app/cards.py`; tables are `cards` and `messages`. All routes need a token and see only the caller's rows; a card that is not yours is `404`.

| Route | Does |
| --- | --- |
| `POST /cards` | Create a card. Body: `app`, `name`, optional `external_id`, `stage` (default `matched`), `notes`, `next_action`, `due_date`. |
| `GET /cards?stage=&app=` | List cards, oldest first. Both filters are optional. |
| `GET /cards/{id}` | Read one card. |
| `PATCH /cards/{id}` | Change only the fields sent: `name`, `stage`, `notes`, `next_action`, `due_date`. `null` clears `next_action` or `due_date`. |
| `POST /cards/{id}/messages` | Add a message. Body: `sender` (`me` or `them`), `body`, optional `sent_at` (default now), `external_id`. |
| `GET /cards/{id}/messages` | List the card's messages by `sent_at`. |

- **A message** is `{"id", "card_id", "external_id", "sender", "body", "sent_at", "handover", "sent_by_autopilot"}`. `handover` is the handover checks a message from the match hit (null when not checked). `sent_by_autopilot` is true for a message autopilot sent alone, so the chat marks it with the Autopilot marker; it is false for the user's own messages, drafts they sent included. The `send_draft` job sets it for an unattended send (see "Drafts"). Messages stored before migration `t59_sent_by_autopilot` are all false.

- **Card summary.** Every card the API returns (these routes, `GET /people`, and later list routes) carries what a row in the app shows, so the app makes no other call:
  - `stalled` and `stage_changed_at` (below);
  - `last_message`: the newest message by `sent_at`, whoever sent it, as `{"sender", "body", "sent_at"}` with the first 100 characters of the body; null when the card has no messages;
  - `hot`: `is_hot_lead()` (see "Review queue"), the same answer the review queue gives;
  - `pending_draft`: the newest pending draft, as the review queue shows it, with `sendable`; null when there is none;
  - `drafts`: the card's draft list, its `pending`, `copied` and `failed` drafts, newest first, so the card can dock them (ADR 0003). Sent, queued and dismissed drafts are not in it;
  - `planned_send`: autopilot's planned send, the draft it sends alone at its `send_at`, with its `timing_reason` (see "Send timing"); null when there is none;
  - `scheduled_send`: the user's scheduled send, their draft that goes out at the `send_at` they chose (Send at, see "Drafts"); null when there is none;
  - `lead_photo_url`: the first photo attached with `POST /cards/{id}/photos`; null when unknown;
  - `pipeline_group`, `reason`, `handover_trigger` and `autopilot_activity`: where the Pipeline lists the card and why (see "Pipeline");
  - `topic`: what the chat is about in a few words, such as `museums`. The call that writes a draft gives it (see "Drafts") and it is stored on the card (`cards.topic`); a later draft replaces it. Empty until the card's first draft.

  `summarize(db, user_id, rows)` in `app/cards.py` builds it from card rows selected with `CARD_COLUMNS`, keeping their order. A route that returns cards selects the rows and returns `summarize(...)`; a new summary field is added there and to `Card`.
- `stage` is one of `matched`, `chatting`, `number_swapped`, `date_set`, `dated`, `seeing_them`, `archived`. Anything else is `422`. `stage_changed_at` on the card is the time of the last stage change; there is no stage history table.
- Stalled is a flag on the card, not a stage. The hourly `mark_stalled` job sets `stalled: true` on a card in `chatting`, `number_swapped` or `date_set` whose last message, from either side, is older than the user's `stalled_after_days` (a card with no messages counts from `stage_changed_at`). A stalled card has `suggested_actions: ["revive", "archive"]`; otherwise the list is empty. A new message from `them` clears the flag, and so does moving the card out of those three stages; archive is `PATCH /cards/{id}` with `stage: archived`.
- `GET /settings` and `PATCH /settings` read and change the user's settings; `PATCH` changes only the fields sent. `stalled_after_days` is a whole number of days, at least 1, default 3. `time_zone` is the phone's time zone (see "Today"). `setup_dismissed` hides "Finish setup" on Today (see "Setup"). `push_name_previews` lets hot-lead and handover pushes name the match (see "Review queue"). `blur_photos` has the app blur faces until tapped; the server only stores it. Both are off by default.
- `PATCH /cards/{id}` also takes `date_rating` (1 to 5) and `date_note`, both null until the user rates the date. A rating needs no stage change, so a date synced into Dated gets rated too, and it counts on the dashboard from the first rating (`date_rated_at`). A good date is a rating of 4 or 5: `is_good_date()` in `app/cards.py` is the only definition, and the card's `good_date` field is its result. The card's `led_to_date` is the chat's outcome label (see "Voice").
- `app` is free text, for example `tinder` or `hinge`.
- `external_id` is the ID the dating app gives the match or message. It is unique per user and app for cards, and per card for messages; a duplicate is `409`. Rows without one are never duplicates.
- **Storing a message from other code:** `insert_message(db, user_id, card_id, external_id, sender, body, sent_at)` in `app/cards.py` is the one way to store a message. It runs everything a new message sets off: for either side, autopilot's planned send to the match is dropped; for `me`, the style profile is queued, a pending handover ends and the card's copied drafts older than the message become `sent`; for `them`, Stalled is cleared, the handover trigger runs and chat autopilot is asked to reply. The route and `upsert_message()` (which skips a message the card already has, and moves a Matched card to Chatting) both call it. Never insert into `messages` yourself.
- **Reading a card from other code:** use `app/card_lookup.py`, which every module can import. `own_card(db, user_id, card_id)` returns the user's card or raises `404` (for a route); `find_card()` returns `None` instead (for a job). `conversation()` is the card's messages as `(sender, body)`, oldest first, `chat_lines()` turns them into `sender: body` prompt lines, and `unanswered()` is the match's messages since the user's last one. Do not write these queries again.

## On the phone

`CardDetailView(client:card:onSaved:)` (`Screens/CardDetailView.swift`) is one card, opened from Today, Review, the Pipeline and a push. It loads the card (`GET /cards/{id}`) and its messages on appear, keeping Details edits not yet saved. `onSaved` runs after anything that can move the card in a list.

- **Header**: `FacePhoto` 340 pt high with the name and "Chatting on Tinder, matched 3d ago" (`Card.createdAt`) on a glass plate, the plate's fill as on Review's. It is the first thing in both tabs. Scrolled past it, the navigation bar shows the face (`Avatar`, 32 pt) and name (`onScrollGeometryChange`).
- **Tabs**: Chat and Details, a segmented picker in a `safeAreaBar` at the top. The card opens on Chat when `Stage.chatsInApp` (Matched, Chatting), else on Details.
- **Chat**: the messages as bubbles, the match's on the left on the fill, the user's on the right in the label color. A time ("Yesterday 7:24 PM") heads the first message and each one an hour or more after the one before; the last message says how long ago it was sent. `AIMarker(.autopilot)` sits under each message with `sentByAutopilot`. The chat opens on the newest message (`ScrollPosition`, scrolled to the bottom after each load).
- **Handover banner** (`HandoverBanner`): when `card.handover` is set, at the end of the chat, so it scrolls at large text sizes. Pending: why autopilot stopped (`reason(_:)` on the trigger codes of the newest match message with a `handover` hit), that message quoted, each suggested reply under AI suggests with Copy, then Hand back and Take over. Taken over: one line and Hand back. Either reloads the card.
- **Composer** (`DraftComposer`, in a bottom `safeAreaBar`, glass over a 72% fill): it docks `card.plannedSend` first, then `card.scheduledSend`, else `card.drafts?.first` by `Draft.status`.
  - Planned send: `PlannedRing` and "Replies around 20:15", the timing reason, the text under Autopilot in an `Inset` (it scrolls above the buttons when it does not fit, at the largest text sizes), then Hold and Send now (only if `sendable`). Send now calls `client.sendNow`, toasts "Sending to Ada…" (no Undo: it goes at once) and calls `sent`. Hold calls `client.hold`, toasts "Held. It waits in Review." and reloads, so the draft docks again as pending. A `409` on either reloads and says why.
  - `pending`: the text editable in an `Inset` under AI draft, then Send if `sendable`, else Copy. Either saves an edit first. A draft that denies being AI says so and offers neither until edited.
  - `copied`: "Copied, not sent yet", the text, Clear (hidden at once, `POST /drafts/{id}/dismiss` after the toast's 5 seconds unless Undo, through `Held`) and Copy again (clipboard only).
  - `failed`: the warning Review shows, the text editable, Copy and Retry (Retry only if `sendable`).
  - No draft: Write draft in Matched and Chatting (`POST /cards/{id}/drafts`, then a reload); nothing from Number swapped on. A `409` (no style profile yet) sets `needsVoice`, and the card pushes `VoiceView`.
  - Send and Retry call `client.sendDraft`, show `Toast.sending` (Undo: `client.undoSend`, then a reload; `409` says it is too late) and call `sent`: the card reloads at once (the draft leaves the dock), then every 3 seconds, at most 4 times, until a new message is in the chat. Copy calls `client.copy`, toasts "Copied. Paste it in Hinge." and reloads, so the draft docks again as copied.
  - **Suggested send time:** `pending` and `copied` show `SuggestedSendTime` in the `Inset` ("Best sent around 20:15 · she's on a roll", from `sendAt` and `timingReason`; nothing once the time has passed, `Draft.suggestedSendAt`). A pending draft the app can send gets `SendAtButton` ("Send at 20:15", VoiceOver adds the day) next to Send: `client.sendDraft(draftID:at:)`, a toast "Goes to Ada at 20:15" with no Undo, and a reload.
  - **Scheduled send** (`card.scheduledSend`), docked before any draft: "Goes out at 20:15", the text, and Cancel (`client.unschedule(draftID:)`, then a reload, so it docks as pending again; `409`: "Too late to cancel the message to Ada."). Screenshots: `t74-card-*.png`, and Review's `t74-review-*.png`.
- **Details**: a plain list under the header: Stage; Next action (a labeled `GrowingField`) with the Due date toggle and day; Notes; for a rated card or a Dated one, the date's rating (`RatingPicker`, nothing selected until rated) and its note; then the match read (`ReadSection`).
  - Edits save as the user makes them: `.autosave` on the whole card compares `Edits` (stage, notes, next action, due date, rating, note), not the whole card, a second after the last change and when the card goes away (popping it, or pushing `VoiceView`). Switching to Chat keeps the debounce running. A load or a save's answer keeps edits the server does not have yet (`take(_:)`). A failed save shows `ErrorRow` under each field whose edit is not saved; tapping it saves again.
  - Reaching Dated unrated opens the rating sheet; "Not now" leaves the rating on Details.
  - Match read: each inference under `AIMarker(.suggests)`, its kind, its `confidenceWord` (Sure, Likely, Guess; "Corrected by you" once corrected), the value and "Evidence: …" in `.subheadline`. Kind and word stack at accessibility sizes. A tap corrects it in an alert (`PATCH /inferences/{id}`).
- **Rating sheet** (`DateRatingSheet(name:onRated:)`, `Screens/DateRatingSheet.swift`): one sheet for the card, Today's dates to rate and the Pipeline's "Rate the date" rows. `RatingPicker` with nothing selected, a note, "Not now" and Save, which waits for a rating. The host saves with `client.update` and no stage change.
