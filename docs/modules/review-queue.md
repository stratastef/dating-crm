# Review queue

All in `app/review.py`. A pending draft waits in the queue until the user sends, copies or dismisses it (Send is `POST /drafts/{id}/send`, see "Drafts"); editing is `PATCH /drafts/{id}`. A copied draft waits until it is sent or cleared.

| Route | Does |
| --- | --- |
| `GET /queue` | List what waits for the user, hot leads first, then oldest first. |
| `POST /drafts/{id}/copy` | Set a `pending` or `failed` draft's `status` to `copied` and `copied_at` to now, and return it. Allowed on any card. `409` from any other status (the detail names it: "the draft is sent"). |
| `POST /drafts/{id}/dismiss` | Set a `pending`, `copied` or `failed` draft's `status` to `dismissed` and return it: Dismiss, or Clear for a copied draft. Releases the calendar holds of the slots the draft offered. `409` from any other status, `502` if Google could not be reached (the draft stays as it was). |

- A queue item is `{"kind", "hot", "card_id", "card_name", "card", "draft", "message", "triggers", "suggestions", "paid_item"}`. Each item carries what the user needs to decide without opening the chat:
  - every item of a card: `card` is its card summary (`Card` in `app/cards.py`: name, lead photo, dating app and the rest; see "Cards and messages");
  - kind `draft`: `draft` holds the draft, whose `kind` is `opener` or `reply`. For a reply, `message` is the message it answers, `{"body", "sent_at"}`: the newest message from the match sent before the draft was written. An opener has none. `draft.sendable` says whether to offer Send or Copy (see "Drafts");
  - kind `copied_draft` (a copied draft not yet in the chat): the same fields as `draft`. It leaves the queue when a newer message from the user is stored on its card or the user clears it with `dismiss`;
  - kind `failed_send` (a draft whose send failed, `status` `failed`): the same fields as `draft`. It leaves the queue when the user retries it (`POST /drafts/{id}/send`), copies it or clears it with `dismiss`. The app may have delivered it before the error, so the app asks the user to check the chat first;
  - kind `handover` (a card whose handover is pending, see "Handover"): `triggers` are the handover checks that fired (`asks_if_ai`, `logistics`, `place_or_exclusivity`, `personal_info`, `sensitive`, or `unavailable` when Jev could not be asked), and `message` is the message that fired them: the newest message from the match with a stored hit. `suggestions` holds the suggested replies. Both are null when no hit is stored;
  - kind `paid_item` (see "Paid items"): `paid_item` holds the proposal, with the candidate's `photo_url`, its `candidate_id` (the app opens the profile from it) and the `cost` the connector reported. `card` and `card_id` are null and `card_name` is the proposal's `name`. It is never hot.
- **Order:** hot leads first, then oldest first across kinds. A draft's age is when it was written, a copied draft's when it was copied, a failed send's when it failed, a paid item's when it was proposed, and a handover's the time of the message that fired it (`shortcut:` in `queue()`: the card does not store when its handover began).
- **A new kind of item** adds its own `kind`, a loop in `queue()` that appends `(time it began to wait, QueueItem)`, and any field it needs on `QueueItem`. The sort does the rest. A draft that waits in a new status needs only that status in the drafts query and in `_DRAFT_KINDS`.
- `is_hot_lead(db, user_id, card_id)` is the only definition of a hot lead: the match sent a message within the last hour, Jev's hot-lead triage flagged a pending draft of the card (`drafts.hot_lead`), the card's handover is pending, or a date is being coordinated (a slot is held for the match, or a message of theirs that hit `logistics` is unanswered). An item's `hot` is its card summary's `hot`.
- `POST /cards/{id}/drafts` calls `notify_if_hot()`, which sends one push at once for a hot lead and nothing otherwise. Call it wherever else an item joins the queue.
- **Discreet pushes.** The push shows on the lock screen, so unless the user turned on push name previews (`PATCH /settings {"push_name_previews": true}`, off by default) `notify_if_hot()` replaces the caller's title and body with "Hot lead" and "Someone replied. A draft is ready.": no name and no text. The card ID stays in the payload either way, so a tap opens the card.
- Undo of a dismissal or a Clear is the app's: Review holds the `dismiss` call for the 5 seconds its Undo toast shows (see On the phone, below). Undo of a Send is the server's, because the message must not leave before the window ends: `POST /drafts/{id}/undo-send` (see "Drafts").

## On the phone

`Screens/QueueView.swift` renders `GET /queue` (above) in a `ScrollView`, hot leads first, with pull to refresh. Its state is `ReviewQueue` (`ios/DatingCRM/ReviewQueue.swift`, `@Observable`): `items`, `load()`, `remove(item)` for an item the server no longer holds, and `dismiss(item)` / `undo(item)`.

- **Faces in glass** (ADR 0009, the one place glass sits on content): `PhotoCard` puts `FacePhoto` behind the item and the plate on Liquid Glass over its lower part, 200 pt below the top. The glass is on the plate's background, not its content (glass turns the black capsule grey), under a 72% fill of the system background, so plate text is `.primary` only; grey text and the AI marker go on an `Inset` (solid background). The Hot badge sits on the soft accent.
- **Every item:** `ItemHeader` (the name, a `NavigationLink(value: card)` that opens `CardDetailView`, and the Hot badge), then per kind: `DraftItem` ("Reply on Tinder" and the time of the answered message, the quote, the draft editable in place under the AI draft marker with its `SuggestedSendTime`, Dismiss and Send or Copy, and Send at next to Send), `CopiedDraftItem` ("Copied for Hinge, not sent yet", the text and its `SuggestedSendTime`, Clear and Copy again), `HandoverItem` (why autopilot stopped, from the trigger codes in `HandoverBanner.reason`, the quote, each suggested reply under AI suggests with Copy, Hand back and Take over), `PaidItemCard` (the item and its cost, the reason, a link to the profile, Decline and Approve). The profile opens in `CandidateProfile`, a sheet with the candidate's photos and bio from `GET /swipes`.
- **Dismiss with Undo:** `dismiss(item)` takes the draft out at once and calls `POST /drafts/{id}/dismiss` only after the undo window (5 s, the toast's time). Undo puts it back where it was and the server never hears of it; a reload meanwhile does not bring it back. A failed dismissal reloads, so the draft returns with the error.
- **Send or Copy** (ADR 0003): `DraftItem` offers Send when `draft.sendable`, else Copy. Either first saves an edit. Send calls `client.sendDraft(draftID:)`, then `QueueView` removes the item and shows `Toast.sending`. Its Undo is `review.undoSend(item)`: `POST /drafts/{id}/undo-send`, then a reload, so the draft comes back as the server has it, pending and editable; too late (`409`), it reloads and says "Too late to undo the message to Ada." Copy puts the text on the clipboard, calls `client.copy(draftID:)`, shows the toast "Copied. Paste it in Hinge." (`QueueItem.datingApp`, private to `QueueView.swift`) and reloads, so the item comes back as `copied_draft`.
- **Copied draft:** Copy again only puts the text on the clipboard, with the same toast. Clear is `review.dismiss(item)` with an Undo toast, like Dismiss. The item leaves on the next load once the user's message shows up in the chat.
- **Send at:** a pending draft the app can send, whose suggested send time is ahead, shows `SendAtButton` between Dismiss and Send; where the three do not fit in a row (larger text), Send at goes above them (`ViewThatFits`). It calls `client.sendDraft(draftID:at:)`; `QueueView` removes the item and toasts "Goes to Ada at 20:15" with Undo (`review.undoSend(item)`) but no ring, since the server holds no Undo wait. Later, the card's composer shows it with Cancel. Review has no scheduled-send item: it holds what waits for the user.
- **Denies being AI:** `Draft.deniesAI` (`guardrail` holds `denies_ai`). Until the user edits the text, `DraftItem` shows why ("It says you're not an AI. Edit it before you send it.") and offers neither Send nor Copy; an edit the server still flags shows the reason again. A copied draft that denies being AI (a migrated v1 draft) offers Clear only.
- **Failed send** (`failed_send`): `DraftItem` again, with "Sending failed. It may still have reached Tinder, so check the chat before you send it again." and Copy and Retry instead of Dismiss and Send. Retry is Send (`POST /drafts/{id}/send`), with the same toast and Undo. A failed send the app cannot send now offers Copy only.
- **A new action** goes in `DraftItem` or a view next to it; one that ends the item calls `review.remove(item)`, one with Undo follows `dismiss`/`undo`. A new item kind gets its own view next to `DraftItem` and a branch in `QueueView`'s `ForEach`, which branches on `item.kind`; kinds the app does not know are skipped.
